## 1. 引言

### 1.1 编写目的

​	**面向开发人员**，明确系统功能边界、性能指标、接口定义及约束条件，作为硬件选型、软件架构设计、编码实现及测试验收的依据。

​	本文档同时承担"需求规格"与"现状架构记录"双重职责：第 2 章的软件架构描述与第 2.4 节的实现进度对照均以当前代码库为准；尚未实现的功能需求按典型自平衡车工程指标给出目标值，并标注「典型值，待实测修订」。

### 1.2 项目背景

​	基于 IMU 传感器与编码器电机打造的自平衡小车。主控 STM32F103C8T6，运行 FreeRTOS 实时操作系统，通过 MPU6050 获取姿态、编码器获取轮速，经串级 PID 解算后驱动双路直流电机，实现两轮动态自平衡，并提供按键 / LED / OLED 本地交互与 ESP8266 WiFi 遥控通道。

### 1.3 系统范围

**范围内**：
- 两轮自平衡控制（姿态解算、直立环 / 速度环 / 转向环）
- 本地人机交互（按键、LED、OLED）
- WiFi 遥控指令通道
- 故障检测与安全保护

**范围外**：
- 上位机 / 手机 App 的开发（仅约定通信协议）
- 电池充放电管理（硬件无电压采样通道）
- Bootloader 与 OTA 升级

## 2. 系统总体描述

### 2.1 系统硬件架构

#### 2.1.1 主控核心板

- **主控芯片**：STM32F103C8T6（Cortex-M3，主频 72MHz）
- **关键内存硬约束**：
  - 芯片内置 RAM 约 **20KB**；
  - 内置 Flash **64KB**。
- **时钟配置**：HSE 8MHz × PLL9 = 72MHz；APB1 = 36MHz（TIM2~4 时钟 ×2 = 72MHz），APB2 = 72MHz；FLASH 等待周期 LATENCY_2。

#### 2.1.2 板级外设资源映射

​	以下映射与 [board_v1_config.h](../project/01-environment_build/bsp/inc/board_v1_config.h) 保持一致，是软件设计的硬件基线：

| 外设 | 用途 | 引脚 / 资源 | 关键参数 |
| ---- | ---- | ---- | ---- |
| I2C1 | MPU6050（0x68/0x69 自动探测）+ SSD1306 OLED（0x3C） | PB6/PB7 | 400kHz，RTOS 互斥锁保护 |
| TIM1 CH1/CH2 | 双电机 PWM（TB6612） | PA8/PA9 | 20kHz |
| TIM2 | 左轮编码器 | PA0/PA1 | X4 倍频，16 位硬件计数 + 中断扩展 32 位 |
| TIM3 | 右轮编码器 | PA6/PA7 | 同上 |
| USART3 | ESP8266（AT 指令） | PB10/PB11 | 115200，TX/RX DMA |
| USART2 | **日志通道**（bsp_dbg：printf / mw_log / HardFault 取证） | PA2(TX)/PA3(RX 未用) | 115200 8N1，寄存器级轮询 TX，上位机串口调试助手查看 |
| EXTI4 / EXTI9_5 | KEY1 / KEY2 | PA4 / PA5 | 低电平有效，ISR 内 20ms 消抖 |
| GPIO 输出 | LED1~LED2 | PC13 / PB13 | - |
| GPIO 输出 | TB6612 IN1/IN2/STBY 等方向控制 | PB0/PB1/PB5/PA10/PB14 | - |
| DWT | 微秒级忙等延时 `bsp_timer_delay_us()` | - | 仅初始化阶段使用 |

#### 2.1.3 设备分类

- **输入设备**：
  - **按键：`KEY1`、`KEY2`**：2 个按键设备（板 v2：原 KEY3 让位 USART2 日志），低电平有效，EXTI 中断 + 20ms 消抖。
  - **编码器：`ENCODER1`（左）、`ENCODER2`（右）**：2 个编码器设备，电机脉冲次数记录，X4 倍频计数。
- **感知设备**：
  - **IMU 传感器：`MPU6050`**：6 轴姿态传感器，获取小车实时姿态（加速度 mg / 角速度 mdps 整数输出）。
- **执行设备**：
  - **电机：`MOTOR_A`、`MOTOR_B`**：TB6612 驱动的 2 路直流减速电机，PWM 调速 + 方向 / 使能 / 刹车控制。
- **HMI 设备**：
  - **LED 灯：`LED1`、`LED2`**（板 v2：原 LED3/PC13 组合保留 LED1，第二盏 PB13）：LED1 运行指示（校准/平衡/调节），LED2 故障指示。
  - **OLED 显示器：`OLED`**：SSD1306 128×64，帧缓冲式显示，小车实时状态显示与操作显示。
- **通信设备**：
  - **WiFi 通信：`ESP8266`**：USART3 + AT 指令引擎，获取外部指令消息与发送消息。

### 2.2 软件层次架构

#### 2.2.0 层次总览与依赖方向

```
┌─────────────────────────────────────────────────┐
│  app        应用层：main、任务创建、HMI 应用       │
├─────────────────────────────────────────────────┤
│  svc        服务层：姿态解算、电机闭环控制          │
├──────────────────────┬──────────────────────────┤
│  middleware  中间件层 │  dal      设备抽象层       │
│  (mw_pid/filter/     │  (registry + 7 类设备接口) │
│   common, 纯算法)    │                          │
├──────────────────────┴──────────────────────────┤
│  bsp        板级支持包：board_v1 + 各 bsp_xxx     │
├─────────────────────────────────────────────────┤
│  third_party  FreeRTOS(V11.1.0+, heap_4) /       │
│               STM32F1xx HAL(V1.1.10) / CMSIS     │
├─────────────────────────────────────────────────┤
│  target      启动文件、链接脚本、时钟、fault 处理   │
└─────────────────────────────────────────────────┘
```

**实际依赖方向（与 CMake 链接关系一致）**：

- `app → svc → {dal, middleware, freertos}`（svc 不直接依赖 bsp，通过 DAL 取设备）
- `bsp → dal`（**倒置设计**，见 2.2.2）
- `dal` 自包含，无任何下层依赖
- `middleware → mw_common`，无 RTOS / DAL 依赖，可在 PC 上单元测试

#### 2.2.1 third_party / target 层（芯片运行时）

- **FreeRTOS**：CM3 端口 + heap_4。关键配置（FreeRTOSConfig.h）：
  - `configTICK_RATE_HZ = 1000`（1ms tick），`configCPU_CLOCK_HZ = 72MHz`
  - `configTOTAL_HEAP_SIZE = 6KB`，静态 + 动态分配并存
  - `configMAX_PRIORITIES = 5`，`configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY = 2`（F103 4 位抢占优先级，内核 IRQ 在最低级 15）
  - `configCHECK_FOR_STACK_OVERFLOW = 2`（栈溢出检测 hook 到 `bkpt`）
- **STM32F1xx HAL**：V1.1.10，启用 CORTEX/RCC/GPIO/DMA/FLASH/PWR/EXTI/UART/I2C/TIM。
- **target/**：启动文件 + 链接脚本（Flash 64K / RAM 20K）+ `fault_handlers.c`（HardFault 汇编包装解析 CFSR/HFSR/栈帧，供调试取证）。

#### 2.2.2 设备抽象层（dal）

- **核心机制**：通用设备注册表 `dal_registry`（静态数组、零动态内存、注册/注销仅限任务上下文，查找只读且 ISR 安全）。每类设备持有私有 registry 实例。
- **接口形态**：ops 函数表 + 设备描述符 `dev_t`（`name / ops / drv_priv / initialized / event_cb`）。DAL 公共 API 是薄封装，转发到 `dev->ops->xxx`。
- **依赖倒置说明**：**BSP 实现 ops 并向 DAL 注册**（类似 Linux driver/model 模式），而非传统 "DAL 包装 BSP"。`dal_imu.h` 等头文件中的 ops 表由 `bsp_mpu6050.c` 等实现，注册设备名如 `"mpu6050"`、`"motor_a"`、`"encoder_left"`。
- **已定义 7 类设备接口**：`dal_imu` / `dal_motor` / `dal_key` / `dal_led` / `dal_encoder` / `dal_display` / `dal_wifi`。
- **事件与 ISR 契约**：BSP 在中断中通过 `dal_xxx_notify_event()` / `dal_motor_notify_fault()` 上报；头文件明确约束回调内禁阻塞、禁调用 DAL API。
- **错误码**：`dal_err.h` 独立枚举（`DAL_OK=0`，负数错误码，含算法类 `DAL_ERR_ALGO_DIVERGE`）。

#### 2.2.3 板级支持层（bsp）

- **`board_v1.c` 是聚合启动入口**：`bsp_init()` 顺序执行 HAL_Init → 时钟配置（72MHz，检查 PLLRDY）→ I2C → KEY → LED → 编码器 → 电机 → OLED → MPU6050（**ESP8266 初始化当前被注释禁用**），任一步失败进 `Error_Handler()`（关中断 + PC13 LED 常亮 + 死循环）。
- **`bsp_timer.c` 为 bsp 内二级抽象**：句柄式多定时器（PWM / 编码器两种模式），bsp_motor / bsp_encoder 建立其上。
- 各驱动实现要点：I2C 带 RTOS 互斥锁与总线恢复序列；TB6612 四态状态机（DISABLED/IDLE/RUNNING/BRAKING），刹车防短路；MPU6050 整数缩放输出（mg / mdps），DRDY/FIFO 暂未实现（返回 NOT_SUPPORTED）；KEY 在 EXTI ISR 内消抖后回调；ESP8266 为 AT 指令引擎 + 自建任务 + DMA 收发。

#### 2.2.4 中间件层（middleware）

- **`mw_common/q15_math.h`**：Q15/Q30 定点运算库（饱和加 / 四舍五入乘 / 除法 / 格式转换），全 static inline，供无 FPU 的 M3 使用。
- **`mw_pid`**：全 Q15 定点 PID。要点：微分作用于测量量（Derivative on Measurement）；条件积分抗饱和；积分器 Q30 全精度累加 + 限幅；微分项可选一阶低通。
- **`mw_filter`**：一阶低通 LPF1、滑动平均 MAVG、一维标量卡尔曼（Q30 协方差全精度）。**无现成互补滤波**，需在 svc_att_algo 中组合实现。

#### 2.2.5 服务层（svc）

采用 4 服务划分（划分依据与任务预算详见《开发手册》5.7）：

- **`svc_att_algo`（姿态解算服务）**：从 `dal_imu` 周期采样（200Hz），互补滤波输出倾角/角速度快照，陀螺仪零偏校准（DAL 注入），数据失效检测。**v1.0 已实现并接入 main.c。**
- **`svc_mot_ctrl`（运动控制服务）**：编码器测速 + 串级 PID（直立/速度/转向环）+ 倒地保护 + 运动指令 API，消费 svc_att_algo 快照输出到 `dal_motor`。**当前为空壳，未实现。**
- **`svc_comm`（通信服务，规划）**：WiFi 连接管理 + 协议解析分发 + 遥测聚合。
- **`svc_monitor`（系统监控服务，规划）**：任务心跳检查、故障码汇集、喂狗策略（IWDG 经 app 注入）。
- 依赖约定：`freertos + mw_* + dal`，不直接依赖 bsp；模式状态机（业务编排）留在 app 层。

#### 2.2.6 应用层（app）

- **`main.c`**：装配入口：bsp_init -> 各服务 init -> app_ctrl_init -> 全部 start -> vTaskStartScheduler。
- **`app_hmi`**：OLED 页渲染（5x7 字库，21x8 字符），供 app_ctrl 2Hz 调用。
- **`freertos_hooks.c`**：静态分配 Idle 任务内存 + 栈溢出 hook（bkpt + 死循环）。

### 2.3 运行时资源预算

​	当前基线（全服务实现后，map 文件实测，Debug 构建）：

| 资源 | 已用 | 总量 | 占用率 |
| ---- | ---- | ---- | ------ |
| Flash (text+data) | ≈ 62.8KB | 64KB | 96%（snprintf 落地 +OLED 字库） |
| RAM (data+bss) | ≈ 19.4KB | 20KB | 97%（余 ~600B 为 MSP/ISR 栈） |

​	RAM 静态占用大头：FreeRTOS heap_4 堆 4KB（动态分配仅 esp8266 任务栈 2KB 与 AT 帧载荷）、6 个静态任务栈合计 4.9KB（att 256w / mot 320w / comm 256w / app 256w / monitor 160w / idle 64w）、OLED 帧缓冲 1KB、svc_comm RX 环形缓冲 256B、app 显示行缓冲 192B。**余量 ~600B 属紧约束**：MSP/ISR 栈共用该余量（_estack 顶端向下）；任务栈按 uxTaskGetStackHighWaterMark 实测后复核裁剪。

## 3. 需求分析

> 每条需求格式：**编号** + 描述 / 指标 / 说明 / 验证方法。指标未特别标注者均为**典型自平衡车工程值，待实测修订**。

### 3.1 设备启动与初始化需求

#### 3.1.1 背景

​	设备上电或复位后需要快速、安全地进入运行状态，确保所有硬件模块就绪、软件环境初始化完成，具备支撑其他应用的能力。

#### 3.1.2 需求详解

##### FR-INIT-001 启动时间

> **描述**：设备从上电到进入就绪（平衡控制可启动）的总时间。
>
> **指标**：≤ **3秒**（典型值）
>
> **说明**：包括外设初始化、RTOS 初始化、设备驱动加载与自检全过程。WiFi 连接允许后台异步完成，不阻塞就绪。
>
> **验证方法**：上电瞬间翻转测试 GPIO，逻辑分析仪测量到"就绪标志 GPIO"翻转的时间；或比较上电时刻与 OLED 就绪页显示时刻。

##### FR-INIT-002 启动时序

> **描述**：设备上电启动阶段划分（本系统无 Bootloader 与 DSP，阶段按实际 init 流程划分）。
>
> **指标**：完整执行所有阶段，任一阶段失败进入安全态（Error_Handler：电机保持禁用 + LED 故障指示）。
>
> **说明**：
>
> | 阶段 | 内容 | 耗时预算 |
> | ---- | ---- | -------- |
> | 芯片初始化 | 启动文件、SystemInit、HAL_Init、时钟配置（72MHz，检查 PLLRDY） | ≤ 50ms |
> | RTOS 初始化 | 任务创建、调度器启动 | ≤ 50ms |
> | 外设初始化 | I2C、TIM（PWM/编码器）、USART、EXTI、GPIO | ≤ 100ms |
> | 设备驱动加载 | MPU6050（含复位序列 + WHO_AM_I 校验）、OLED、电机、编码器、按键、LED | ≤ 500ms（含 MPU6050 复位等待） |
> | 设备自检 | 见 FR-INIT-003 | ≤ 200ms |
> | 网络初始化 | ESP8266 AT 握手 + WiFi 连接 | 后台异步，≤ 10s |
>
> **验证方法**：各阶段入口/出口翻转测试 GPIO + 逻辑分析仪分段测量。

##### FR-INIT-003 设备自检

> **描述**：设备上电时对板上设备进行健康检测。
>
> **指标**：MPU6050 WHO_AM_I 校验通过；电机驱动进入 DISABLED 安全态；各 DAL 设备注册齐全且初始化成功。
>
> **说明**：自检失败不得静默忽略——关键设备（IMU、电机）失败直接进 Error_Handler；非关键设备（ESP8266、OLED）失败降级运行并在状态中上报。
>
> **验证方法**：断开 / 短路 I2C 器件模拟故障，验证错误路径与 LED 指示；正常上电检查自检通过率 100%。

##### FR-INIT-004 陀螺仪零偏校准

> **描述**：进入平衡模式前，小车需静止完成陀螺仪零偏校准。
>
> **指标**：校准采样 ≥ 200 组，静置时间 ≤ 2s；校准期间 LED 指示校准状态，检测到运动则校准失败并要求重试。
>
> **说明**：零偏漂移是平衡角度误差的主要来源，须在上电与长时间运行后（温漂）提供重校准入口（按键触发）。
>
> **验证方法**：串口打印零偏前后角度输出对比；倾斜/移动小车验证校准拒绝逻辑。

### 3.2 姿态解算需求

#### 3.2.1 背景

​	姿态解算是自平衡控制的核心反馈源：由 MPU6050 加速度计与陀螺仪数据融合得到车体倾角与角速度，供平衡控制环使用。**当前 svc_att_algo 为空壳，本节为待实现目标。**

#### 3.2.2 需求详解

##### FR-ATT-001 数据采样率

> **描述**：IMU 原始数据读取频率。
>
> **指标**：≥ **100Hz**（典型值；与控制周期匹配建议 200Hz）。
>
> **说明**：当前 MPU6050 驱动配置 DLPF=6（加速度计 / 陀螺仪带宽均仅 **5Hz**，陀螺仪内部采样率 1kHz），对平衡控制偏低，**建议调整 DLPF=3~4（带宽约 20~44Hz）后再定稿本条指标**；DRDY/FIFO 未实现，采用轮询读取，后续可启用 DRDY 中断驱动采样。
>
> **验证方法**：GPIO 翻转测量采样周期；统计单位时间样本数。

##### FR-ATT-002 姿态融合算法

> **描述**：以互补滤波（或一维卡尔曼）融合加速度计角度与陀螺仪积分角度，输出车体倾角（roll 或 pitch，取决于安装方向）与角速度。
>
> **指标**：
> - 姿态角静态精度：误差 ≤ **±2°**（典型值）
> - 姿态角分辨率：0.1°
> - 动态响应：≥ 50Hz 带宽，振动环境下角度抖动 ≤ 1°（RMS）
>
> **说明**：实现基于 `mw_filter`（LPF1 / Kalman1D）组合；全程 Q15 定点运算（无 FPU），禁止在解算路径使用浮点。加速度计在加减速时不可信，融合权重须偏向陀螺仪短时积分。
>
> **验证方法**：静态放置对比倾角仪读数；手动摆动小车记录阶跃响应；PC 侧单元测试（录制 IMU 数据回放）。

##### FR-ATT-003 数据有效性监测

> **描述**：检测 IMU 数据异常（读取失败、数据停滞）。
>
> **指标**：连续 ≥ 3 次读取失败或数据超过 50ms 未更新，置位姿态失效标志并触发电机停机保护（见 FR-FAULT-001）。
>
> **验证方法**：拔排线 / 断电模拟 I2C 故障，测量从故障到电机停机的延时。

### 3.3 平衡控制需求

#### 3.3.1 背景

​	平衡控制是本系统的核心功能：以姿态角反馈驱动电机，使车体保持动态直立，并响应速度 / 转向指令。**当前 svc_mot_ctrl 为空壳，本节为待实现目标。**

#### 3.3.2 需求详解

##### FR-CTRL-001 控制周期

> **描述**：平衡控制环（直立环）的解算周期。
>
> **指标**：**5ms（200Hz）**，抖动 ≤ 1ms（典型值）。
>
> **说明**：由高优先级 FreeRTOS 任务实现，控制路径内禁止阻塞调用（I2C 读取采用非阻塞或预读缓冲）。
>
> **验证方法**：任务内翻转 GPIO + 逻辑分析仪测量周期与抖动。

##### FR-CTRL-002 串级控制结构

> **描述**：采用直立环（内环 / 快环）+ 速度环（外环 / 慢环）+ 转向环的串级 PID 结构。
>
> **指标**：
> - 直立环：200Hz，控制倾角，是平衡的主要回路
> - 速度环：50Hz，以编码器速度反馈调节目标倾角，防止车体持续漂移
> - 转向环：100Hz，以两轮速度差实现转向
>
> **说明**：PID 实现复用 `mw_pid`（Q15 定点、微分先行、条件抗饱和）。参数需提供编译期默认值 + 运行期在线调参接口（供 FR-COMM 遥调）。
>
> **验证方法**：分环开环 / 闭环测试；阶跃干扰（轻推车体）记录恢复过程。

##### FR-CTRL-003 平衡性能

> **描述**：车体自主保持直立的能力。
>
> **指标**（典型值）：
> - 静态平衡：倾角波动 ≤ ±2°
> - 抗扰恢复：±10° 瞬时扰动后 ≤ 1.5s 恢复平衡，恢复过程无持续振荡（超调 ≤ 1 次）
> - 平衡状态下轮子位置漂移 ≤ 0.5m / min
>
> **验证方法**：逻辑分析仪 / 上位机记录倾角曲线；地面划线测量漂移；定量的推力扰动测试。

##### FR-CTRL-004 倒地保护

> **描述**：车体倾角超过安全阈值时立即停止电机输出，防止飞车与机械损坏。
>
> **指标**：倾角 > **45°**（典型值）时 ≤ **10ms** 内 PWM 归零并刹车（或滑行，视实测定）；恢复直立范围内可自动（或按键）重新进入平衡。
>
> **验证方法**：手持车体缓慢倾斜过阈值，示波器测 PWM 关断延时；跌落测试验证无飞转。

### 3.4 电机驱动需求

##### FR-MOT-001 PWM 调速

> **描述**：双电机独立 PWM 调速与方向控制（TB6612，TIM1 20kHz）。
>
> **指标**：PWM 频率 20kHz（已实现）；占空比分辨率 0~100%（Q15 表示）；正 / 反转 / 停止 / 刹车四态切换无桥臂短路风险。
>
> **说明**：当前 bsp_motor 已实现四态状态机与刹车防短路；svc 层输出限幅 ±100% 需求由 mw_pid 抗饱和保证。
>
> **验证方法**：示波器测量 PWM 频率 / 占空比线性度；逻辑分析仪验证方向切换时序。

##### FR-MOT-002 电机使能与安全态

> **描述**：电机具备全局使能（STBY）控制，故障时统一进入 DISABLED 安全态。
>
> **指标**：任何 FR-FAULT 触发后，两电机在 10ms 内进入 DISABLED / 制动；上电默认 DISABLED。
>
> **验证方法**：注入各故障源，测 PWM 关断延时。

### 3.5 编码器测速需求

##### FR-ENC-001 位置与速度测量

> **描述**：双路编码器 X4 倍频计数，硬件 16 位计数经中断扩展为 32 位，供速度环与里程统计。
>
> **指标**：X4 倍频（已实现）；测速刷新率 ≥ 100Hz；速度测量覆盖 ±最大线速度，无方向歧义。
>
> **说明**：速度解算（M 法：Δcount / Δt）在 svc 或 mw 层实现，注意低速量化误差。
>
> **验证方法**：已知直径车轮滚动整圈核对计数；对比示波器测 PWM 占空比与计算速度的线性关系。

### 3.6 人机交互需求

##### FR-HMI-001 按键功能

> **描述**：KEY1~KEY2 功能定义（20ms 消抖已实现，EXTI 中断 + 事件回调）。
>
> **指标**：响应延时 ≤ 50ms；长按 / 短按可区分（典型值：短按 < 500ms，长按 ≥ 1s）。
>
> **说明**：功能分配（板 v2 定稿）：KEY1 启动平衡（校准+启动）；KEY2 停止平衡（IDLE）。原 KEY3 急停功能已随板改裁掉，急停语义由通信指令 0x13 承担。
>
> **验证方法**：逻辑分析仪测按键到 LED 响应延时；连击测试验证消抖。

##### FR-HMI-002 LED 状态指示

> **描述**：LED1~LED2 指示系统状态。
>
> **指标**：状态集合至少包含：初始化 / 故障（Error_Handler 中 PC13 常亮，已实现）/ 平衡运行 / 校准中 / WiFi 连接状态；状态切换可见延时 ≤ 100ms。
>
> **验证方法**：逐状态目视核对；注入故障验证指示。

##### FR-HMI-003 OLED 显示

> **描述**：OLED（128×64 帧缓冲，dal_display）显示小车实时状态。
>
> **指标**：刷新率 ≥ 5Hz（典型值）；显示内容包括：当前倾角、目标 / 实际速度、模式、WiFi 状态、故障码；显示任务不得阻塞控制任务（低优先级，异步 flush）。
>
> **验证方法**：目视核对刷新流畅度；逻辑分析仪确认显示 I2C 事务不抢占控制环采样。
>
> **实现说明（v1.0）**：实际以 2Hz 刷新（app_ctrl 任务内 500ms 节拍，复用而非新建显示任务--RAM 无独立任务栈余量）；显示为状态页（模式/倾角/角速度/轮速/占空比/状态）与 PID 参数页（TUNING 模式自动切换）。逐行 draw + flush_async，控制环优先级 4 高于显示路径（优先级 2），I2C 互斥按优先级天花板自然保护。WiFi 状态页待 ESP8266 联网模式接入后补充。

### 3.7 WiFi 通信需求

##### FR-COMM-001 连接管理

> **描述**：ESP8266（USART3 + AT 引擎）以 STA 模式接入指定 AP，并建立 TCP 连接至上位机。
>
> **指标**：上电到 WiFi 就绪 ≤ 10s（典型值）；断线后自动重连，重连间隔 ≤ 5s；连接状态可查询并上报 LED / OLED。
>
> **说明**：驱动已完成（AT 引擎 + 自建任务 + DMA），board_v1 初始化已启用。svc_comm 当前以 RAW_SERIAL 透传模式运行（不连 WiFi，ssid 配置为 NULL 时自动进入）；WiFi STA 连接由配置启用。WiFi 初始化/连接失败不阻塞平衡功能。
>
> **验证方法**：路由器侧观察连接时间；断网 / 断电测试自动重连；测上电到平衡就绪不受 WiFi 阻塞。

##### FR-COMM-002 遥控指令

> **描述**：接收上位机指令：启停、速度 / 转向设定、PID 参数遥调；回传遥测数据（倾角、速度、PWM）。
>
> **指标**：指令端到端响应 ≤ **100ms**（典型值）；遥测回传 ≥ 10Hz；协议格式 **TBD**（建议帧头 + 长度 + 校验的定长帧）。
>
> **验证方法**：上位机打时间戳测指令往返；丢包 / 错帧注入验证协议健壮性。

### 3.8 故障与保护需求

##### FR-FAULT-001 传感失效保护

> **描述**：IMU 数据失效（FR-ATT-003）或编码器读数异常时停止电机输出。
>
> **指标**：故障检测到电机停止 ≤ 50ms；故障状态锁定，需人工确认（按键）后恢复。
>
> **验证方法**：模拟传感器故障，测量保护延时与恢复流程。

##### FR-FAULT-002 电机故障处理

> **描述**：dal_motor 故障回调（BSP ISR 中 `dal_motor_notify_fault()`）触发时进入安全态并指示。
>
> **说明**：TB6612 无电流反馈，当前故障源主要为驱动状态机异常；若硬件后续增加电流采样另行扩展。
>
> **验证方法**：代码审查回调路径 + 故障注入测试。

##### FR-FAULT-003 控制任务健康监测

> **描述**：监控平衡控制任务的存活（心跳 / 喂狗机制，建议 IWDG 看门狗）。
>
> **指标**：控制任务卡死 > 100ms 触发系统复位；复位后默认安全态（电机 DISABLED）。
>
> **说明**：IWDG 当前未启用（hal_conf 中禁用），列为待实现项。
>
> **验证方法**：任务内注入死循环，验证看门狗复位与上电安全态。

##### FR-FAULT-004 故障可观测性

> **描述**：故障发生时保留可观测证据：错误码 / 错误计数器（FR 3.8 各项）、HardFault 现场解析。
>
> **说明**：fault_handlers 已具备 CFSR / 栈帧解析（输出通道待重定向）；日志系统（LOG_LEVEL 四级裁剪，ERROR/WARN/INFO/DEBUG）列为待实现项。
>
> **验证方法**：人为制造 HardFault（空指针调用），核对调试器输出的栈帧与实际调用现场一致。

## 5. 非功能需求

### NFR-01 内存约束

- RAM 总量 20KB 为**硬约束**：任务栈、缓冲静态优先；FreeRTOS heap 已按最终任务规模复核裁剪（6KB -> 4KB，动态分配仅 esp8266 任务 2KB）；
- 每新增任务须核算栈深度（`uxTaskGetStackHighWaterMark` 实测），栈溢出检测（level 2）常开；
- Flash 64KB，当前基线 90%，Release 构建须启用 `-Os`（当前 Debug 构建仅用于开发）。

### NFR-02 实时性

- 中断优先级约定：`MAX_SYSCALL_INTERRUPT_PRIORITY = 2`，使用 FreeRTOS API 的 ISR 优先级数值必须 ≥ 2；内核 IRQ 位于最低级 15；
- ISR 只做标志 / 队列操作，后处理在任务上下文（按键消抖已在 ISR 中，为既有实现，其计算量极小可接受）；
- 控制路径（采样 → 解算 → PWM 输出）总延时预算 ≤ 2ms，路径内禁止阻塞调用与浮点运算。

### NFR-03 可靠性

- 栈溢出检测 + HardFault 取证常开；
- 看门狗（IWDG）上线前必须启用（见 FR-FAULT-003）；
- 时钟切换后必须检查稳定标志（PLLRDY，现有实现已遵循）。

### NFR-04 可测试性

- middleware（mw_pid / mw_filter / q15_math）为纯整数运算、零平台依赖，**必须在 PC 侧建立单元测试**（Unity/CppUTest），覆盖饱和 / 抗积分饱和 / 卡尔曼收敛等边界；
- 姿态解算与控制环支持数据回放测试（录制 IMU / 编码器数据离线重放）；
- 构建提供 `check` 目标触发静态分析（cppcheck）。

### NFR-05 可维护性

- 日志系统按 LOG_LEVEL 四级编译期裁剪，可重定向 UART / ITM；
- 代码遵循全局编码规范（命名 / Doxygen 中文注释 / 模块版本注释）；
- 固件版本宏 `FW_VERSION_MAJOR/MINOR/PATCH` 待引入，OLED / 遥测可读。
