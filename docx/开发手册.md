## 1. 项目概览

### 1.1 项目简介

基于 STM32F103C8T6 + FreeRTOS 的两轮自平衡小车：

- **感知**：MPU6050（I2C1）获取姿态，双路编码器（TIM2/TIM3）获取轮速
- **执行**：TB6612 双电机驱动（TIM1 20kHz PWM）
- **交互**：3 按键（EXTI）、3 LED、SSD1306 OLED（I2C1）
- **通信**：ESP8266（USART3 + AT 指令引擎）

### 1.2 目录结构

```
stm32_project/
├── docx/                          # 文档（需求分析、开发手册、01-环境搭建存档）
└── project/01-environment_build/  # 工程根
    ├── CMakeLists.txt             # 根构建脚本（依赖顺序：target->third_party->bsp->dal->mw->svc->app）
    ├── cmake/
    │   └── stm32f1-gcc.cmake      # 交叉编译工具链文件
    ├── target/stm32_f103c8t6/     # 启动文件、链接脚本、时钟、fault 处理
    ├── third_party/
    │   ├── FreeRTOS/              # git 子模块（FreeRTOS-Kernel）
    │   ├── STM32F1xx_HAL/         # HAL 驱动（注意：见 9. 已知问题）
    │   └── stm32f1xx_hal_conf.h   # HAL 模块裁剪配置
    ├── bsp/                       # 板级支持包（board_v1 + 各 bsp_xxx 驱动）

    │   └── src/                   # board_v1.c + 各 bsp_xxx.c
    ├── dal/                       # 设备抽象层（registry + 7 类设备接口，inc/src 平铺）

    ├── svc/                       # 服务层（svc_att_algo、svc_mot_ctrl）
    ├── app/                       # 应用层（main.c、app_hmi、freertos_hooks）

```

### 1.3 关键参数速查

| 项目 | 值 |
| ---- | ---- |
| MCU | STM32F103C8T6，Cortex-M3 @ 72MHz，RAM 20KB，Flash 64KB |
| 时钟 | HSE 8MHz × PLL9，APB1=36MHz，APB2=72MHz，FLASH LATENCY_2 |
| FreeRTOS | V11.1.0+ 内核（CM3 端口 + heap_4），1ms tick，堆 6KB，5 级优先级 |
| HAL | STM32F1xx HAL V1.1.10 |
| 当前资源占用 | Flash ≈ 32.3KB（50%），RAM ≈ 11.9KB（59%），Debug 构建 |

## 3. 构建、烧录与产物

### 3.1 配置与编译

```bash
cd project/01-environment_build

# 首次配置（工具链文件在根 CMakeLists 中已内置默认，无需手动指定）
cmake -B build

# 编译
cmake --build build -j$(nproc)
```

要点：

- 根 [CMakeLists.txt](../project/01-environment_build/CMakeLists.txt) 默认 `CMAKE_BUILD_TYPE=Debug`（`-Og -g3`）；发布用 `cmake -B build -DCMAKE_BUILD_TYPE=MinSizeRel`（`-Os`，省 Flash）
- 编译选项（[stm32f1-gcc.cmake](../project/01-environment_build/cmake/stm32f1-gcc.cmake)）：`-mcpu=cortex-m3 -mthumb -mfloat-abi=soft -Wall -Wextra -Wshadow -ffunction-sections -fdata-sections`
- 链接选项（app/CMakeLists.txt）：`--specs=nano.specs`（**20KB RAM 必须**用 newlib-nano）、`--specs=nosys.specs`、`-Wl,--gc-sections`、`-Wl,--wrap=malloc/free`
- 每次链接自动执行 `--print-memory-usage`，**每次提交前关注 RAM 余量**（见 5.5 资源预算）

### 3.2 烧录

```bash
cmake --build build --target flash
# 等价于：
# openocd -f interface/stlink.cfg -f target/stm32f1x.cfg \
#         -c "program build/app/stm32f103_test.elf verify reset exit"
```

前置条件：ST-Link 已接好、目标板供电正常。烧录完成后自动复位运行。

## 4. 调试

### 4.1 GDB + OpenOCD（命令行）

```bash
# 终端 1：启动 OpenOCD GDB 服务（3333 端口）
openocd -f interface/stlink.cfg -f target/stm32f1x.cfg

# 终端 2：连接调试
arm-none-eabi-gdb build/app/stm32f103_test.elf
(gdb) target remote localhost:3333
(gdb) monitor reset halt
(gdb) break main
(gdb) continue
```

常用操作：

| 需求 | 命令 |
| ---- | ---- |
| 复位并停在 main | `monitor reset halt` + `break main` + `c` |
| 单步（不进函数 / 进入） | `next` / `step` |
| 查看寄存器 / 调用栈 | `info registers` / `bt` |
| 重启目标 | `monitor reset run` |

### 4.2 FreeRTOS 任务状态（GDB）

```gdb
(gdb) p pxCurrentTCB                       # 当前任务控制块
(gdb) p ((TCB_t*)pxCurrentTCB)->pcTaskName # 任务名
(gdb) p pxReadyTasksLists                  # 就绪链表（每个优先级一条）
```

任务栈水位建议在代码里用 `uxTaskGetStackHighWaterMark()` 实测，量产前每任务留 30% 余量。

### 4.3 HardFault 取证

`target/stm32_f103c8t6/fault_handlers.c` 已实现完整取证：HardFault_Handler 为汇编包装（按 EXC_RETURN 的 bit2 选 MSP/PSP），C 部分解析并打印：

- CFSR / HFSR / 各 Fault 状态位
- 异常栈帧：R0-R3 / R12 / LR / PC / xPSR
- MSP / PSP / EXC_RETURN

**使用方法**：调试器连着时直接触发（代码里 `bkpt #0` 停在断点），结合打印的 PC/LR 用 `bt` 定位出错指令。串口 printf 输出通道尚未接（见 9. 已知问题），目前取证信息只在调试器下可见。

### 4.4 逻辑分析仪（硬实时测量）

约定测量点（翻转 GPIO + 逻辑分析仪，代替 printf）：

| 测量点 | GPIO（建议） | 用途 |
| ------ | ---- | ---- |
| 控制周期 | 预留（如 PB15） | 任务入口翻转，测周期与抖动 |
| ISR 耗时 | 预留 | ISR 入口/出口翻转，验证"ISR 只做标志位" |
| 启动各阶段 | 预留 | 各 init 前后翻转，对照 SRS FR-INIT-002 时序预算 |

## 5. 软件架构指南

### 5.1 六层结构与依赖规则

```
app（应用：main、任务创建、HMI 应用）
 └─> svc（服务：姿态解算、电机闭环控制）
      ├─> middleware（纯算法：pid / filter / q15，无平台依赖）
      └─> dal（设备抽象：registry + ops 接口）
           └── bsp 实现 ops 并注册（依赖倒置！）
bsp（板级：board_v1 + 外设驱动） ──> third_party（FreeRTOS + HAL）──> target（启动/链接脚本）
```

**硬性依赖规则**（Code Review 检查项）：

1. `svc` **禁止** include `bsp_*.h` / HAL 头文件 -- 一切设备访问走 `dal_*` API
2. `middleware` **禁止**依赖 RTOS / DAL / HAL -- 保持可在 PC 上单元测试
3. `dal` 头文件是双向契约：上层（svc/app）调用公共 API，下层（bsp）实现 ops 表并向 registry 注册 -- 这是**有意的依赖倒置**（类似 Linux driver/model），不是违规
4. `app` 仅在初始化阶段接触 bsp（`bsp_init()`），运行期与 svc/dal 交互
5. `third_party` / `target` 一律不反向依赖上层

各层职责与现状详见《需求分析》2.2 节；实现进度对照见其 2.4 节。

### 5.2 DAL 设备模型（核心机制）

每类设备 = **一个 ops 函数表 + 一个私有注册表**：

```c
/* dal 侧定义接口（以 dal_imu 为例） */
typedef struct {
    int (*read)(struct dal_imu_dev *dev, dal_imu_data_t *out);
    int (*set_odr)(struct dal_imu_dev *dev, dal_imu_odr_t odr);
    /* ... */
} dal_imu_ops_t;

struct dal_imu_dev {
    const char          *name;      /* 设备名，bsp 注册前填充 */
    const dal_imu_ops_t *ops;       /* bsp 实现的函数表 */
    void                *drv_priv;  /* bsp 驱动私有数据 */
    bool                 initialized;
    dal_imu_event_callback_t event_cb;
};
```

**使用方（svc/app）**：按名字取设备，然后调 DAL 薄封装 API：

```c
dal_imu_dev_t *imu = dal_imu_get_dev("mpu6050");
dal_imu_data_t data;
if (dal_imu_read(imu, &data) == DAL_OK) { /* data.accel_mg / data.gyro_mdps */ }
```

设备注册名速查见**附录 A**。

**线程/中断安全契约**（以 `dal_registry.h` 注释为权威）：

- `register / unregister` 仅限任务上下文
- `find / foreach` 纯只读，ISR 安全
- 事件回调在 **ISR 上下文**执行（如 `dal_key_notify_event()` 由 EXTI ISR 调用）：**回调内禁止阻塞、禁止再调 DAL API**

### 5.3 错误码体系

两套独立枚举，bsp 驱动内部负责映射：

| 层 | 头文件 | 约定 |
| ---- | ---- | ---- |
| BSP | `bsp/inc/bsp_err.h` | `BSP_OK=0`，`BSP_ERR_*` 负数；`bsp_is_ok()/bsp_is_err()` 内联判断 |
| DAL | `dal/inc/dal_err.h` | `DAL_OK=0`，`DAL_ERR_*` 负数（含算法类 `DAL_ERR_ALGO_DIVERGE`） |

**规则**：对外返回 int 的 API 一律 0 成功、负数失败；调用处必须检查。

### 5.4 RTOS 约定

FreeRTOS 配置（`third_party/FreeRTOS/Config/FreeRTOSConfig.h`）与项目约定：

| 项 | 值 | 约定 |
| ---- | ---- | ---- |
| tick | 1ms | 时间相关指标一律换算为 tick 数 |
| 优先级 | 0~4（数值大优先） | **0=Idle 保留**；建议分配：控制任务=4（最高）、采样/通信=3、HMI=2、日志=1 |
| 中断优先级 | 4 位抢占式 | 用 FreeRTOS API 的 ISR，其 NVIC 优先级数值 **≥ 2**（`configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY`）；内核 IRQ 固定 15 |
| 堆 | heap_4 共 6KB | 优先静态创建（`xTaskCreateStatic`）；新增动态分配前先核算 |
| 栈检测 | level 2（fill pattern） | 溢出触发 `vApplicationStackOverflowHook`（bkpt + 死循环） |

**任务设计规则**：

1. ISR 只做标志位 / 队列操作，后处理在任务上下文（现行例外：KEY 消抖在 EXTI ISR 内，计算量极小，可接受）
2. 控制路径（采样->解算->PWM）禁止阻塞调用与浮点运算
3. 共享变量 `volatile`；多字节共享访问走临界区或队列
4. 任务间数据流优先用队列 / 信号量，避免裸全局变量

### 5.5 资源预算（RAM 20KB 硬约束）

当前基线（svc/app 空壳）：**RAM 11.9KB / 20KB**。静态大头：

| 占用 | 大小 |
| ---- | ---- |
| FreeRTOS heap_4 堆 | 6KB |
| OLED 帧缓冲 | 1KB |
| ESP8266 DMA 缓冲 | 512B |

**新增任务/缓冲前先查表**：估算静态分配 + 栈深（每任务 128~512 word），`--print-memory-usage` 结果写进 commit message。RAM 逼近上限时优先砍 heap_4 尺寸。

### 5.6 定点运算约定（无 FPU）

M3 无 FPU，**控制与解算路径禁止浮点**（软浮点库又大又慢）：

- 使用 `middleware/mw_common/inc/q15_math.h`：`q15_t`（±1.0）/ `q30_t`（±2.0），饱和加、四舍五入乘、防溢出除
- PID 用 `mw_pid`（已实现：微分先行、条件抗饱和、Q30 积分器）
- 滤波用 `mw_filter`（LPF1 / MAVG / Kalman1D）
- 浮点仅允许出现在：初始化参数换算、调试打印（且需评估体积影响）

## 6. 模块开发流程

### 6.1 新增一个 BSP 设备驱动（模板）

以"新增 bsp_xxx 驱动并注册到 DAL"为例，**标准五步**：

1. **数据手册摘要**：先在模块头注释里写清关键寄存器 / 时序 / 参考文档（DS/AN 编号）
2. **引脚与资源定义**：在 `bsp/inc/board_v1_config.h` 集中添加引脚宏（**禁止在驱动 .c 里散落硬编码引脚**）；对照《需求分析》2.1.2 映射表确认无外设资源冲突
3. **实现驱动** `bsp/src/bsp_xxx.c` + `bsp/inc/bsp_xxx.h`：
   - 提供 init 函数（含错误处理，失败返回 `BSP_ERR_*`）
   - 若是 DAL 设备：实现对应 `dal_xxx_ops_t` 函数表，模块内静态实例化 `dal_xxx_dev_t`（填 name/ops/drv_priv），init 成功后 `dal_xxx_register()`
   - 多实例设备参考 `bsp_motor.c`（共享句柄引用计数）；需要定时器用 `bsp_timer_open()` 句柄式抽象，**不直接摸 TIM 寄存器**
4. **挂接构建**：`bsp/CMakeLists.txt` 加入源文件
5. **挂接启动**：`bsp/src/board_v1.c` 的 `bsp_init()` 中按正确顺序调用（输入->感知->执行->显示->通信），失败路径可测试

### 6.2 新增一个 DAL 设备接口

当引入**新的设备类别**（现有 7 类之外）时：

1. `dal/inc/dal_xxx.h` / `dal/src/dal_xxx.c`：定义 ops 表、dev 结构、公共 API（薄封装 + 注册校验）、事件回调与 `notify` 接口（供 BSP ISR 调用）
2. 头文件写明 ISR 安全契约（哪些函数可 ISR 调用、回调上下文限制）
3. 私有 registry 实例（静态数组，容量按实际设备数 + 小余量）
4. 错误码补充进 `dal_err.h`（若有新语义）
5. `dal/CMakeLists.txt` 挂接

### 6.3 新增 middleware 模块

1. 目录 `middleware/mw_xxx/`（inc/ + src/ + CMakeLists.txt），参考 `mw_pid` 结构
2. 只依赖 `mw_common`；**不得** include FreeRTOS / dal / HAL 任何头文件
3. 全 Q15/Q30 定点、纯函数、可重入（无静态状态，或状态全在调用方传入的句柄里）
4. **必须同步提供 PC 侧单元测试**（Unity，宿主机 gcc 编译运行；测试目录规划见 9. 待办）

### 6.4 新增 svc 服务模块

1. 目录 `svc/svc_xxx/`（inc/ + src/ + CMakeLists.txt），CMake 链接 `freertos_kernel + dal + 所需 mw_*`（参考 svc 现有 CMake，**不依赖 bsp**）
2. 典型形态：一个高优先级周期任务（`vTaskDelayUntil` 定周期）+ 对外 API（init/start/stop/set_xxx）
3. 设备获取一律 `dal_xxx_get_dev("名字")`；失败要有降级路径（记错误码，不崩）
4. **挂接进固件**：`svc/CMakeLists.txt` 已含子目录；还需在 `app/CMakeLists.txt` 的 `target_link_libraries` 里加 `svc_xxx`（**当前漏链 svc 是已知问题，见 9**）

### 6.5 新增 app 任务

1. 在 `app/` 下建模块（如 `app_hmi`）或直接扩展 main.c；任务在 `bsp_init()` 成功后、`vTaskStartScheduler()` 前创建
2. 优先 `xTaskCreateStatic`（栈/TCB 静态分配，规避堆碎片）
3. 每个任务注释写明：职责、优先级依据、栈大小依据、最坏执行时间预估

### 6.6 开发顺序建议（针对自平衡目标）

```
① svc_att_algo  : dal_imu 轮询读取 + mw_filter 互补滤波 -> OLED/调试器打印角度验证

④ 速度环/转向环 : dal_encoder 测速 -> 串级 PID
⑤ HMI           : 按键启停/校准、LED 状态机、OLED 页面
⑥ WiFi          : 启用 bsp_esp8266_init（先核 RAM 预算）+ 遥控协议
```

## 7. 编码规范

> 本节为项目级强约束摘要；与个人全局规范冲突时**以本节为准**（嵌入式实测修正）。

### 7.1 命名

| 对象 | 规则 | 示例 |
| ---- | ---- | ---- |
| 模块/文件 | `lower_case`，bsp 前缀 `bsp_`，dal 前缀 `dal_`，mw 前缀 `mw_` | `bsp_mpu6050.c` |
| 函数 | `module_verbnoun()` | `dal_motor_set_duty()` |
| 变量 | `camelCase`；局部可用 `l_` 前缀 | `l_retryCount` |
| 宏/常量 | `UPPER_CASE` | `MPU6050_DEFAULT_DLPF` |
| 类型 | `ModuleName_t` 后缀；ops 表 `xxx_ops_t`；设备句柄 `xxx_dev_t` | `dal_imu_dev_t` |

### 7.2 注释（Doxygen，中文）

- 文件头必写：`@file @brief` + 职责/依赖 + 参考文档（DS/AN 编号）+ `@author @version`，并维护**版本变更注释**（现有驱动的 v1.2->v1.6 修订记录就是范例）
- 公开 API 必写：`@brief @param @return` + `@note`（中断安全？可重入？）+ `@warning`（危险操作）
- 特殊/绕弯逻辑注释 **WHY 而非 WHAT**（如 bsp_i2c 总线恢复序列的钳位检测原因）
- 枚举/结构体字段用行尾 `/**< 说明 */`
- 禁止 `//` 风格注释函数/模块；禁用非标准标签 `@description`

### 7.3 C 语言规则

- C99；空参显式 `void`：`int foo(void)`
- 警告基线：`-Wall -Wextra -Wshadow`（工具链已开），新增代码零告警
- 外设寄存器一律用 CMSIS `__IO` 限定符 / HAL API，**禁止裸写硬编码外设地址**
- 时钟切换后必须查稳定标志（`PLLRDY` 等），**禁止纯软件延时等时钟**（现有 board_v1 已遵循）
- 关键共享数据：`volatile` + 必要处 `__DSB()/__ISB()`

### 7.4 ISR 规则

- 只做标志位 / 队列 / 信号量操作，后处理在任务上下文
- 调 FreeRTOS FromISR API 的中断，NVIC 优先级数值 ≥ 2
- 回调链（如 `dal_key_notify_event`）在 ISR 上下文执行，订阅方回调同样受本规则约束
- 硬实时路径禁止 printf / 断点，用 GPIO 翻转 + 逻辑分析仪

### 7.5 Git 与提交

- 提交信息：**Conventional Commits**（`feat:` / `fix:` / `docs:` / `refactor:` / `bsp:` 等类型前缀 + 模块范围；历史示例 `bsp:led,key;dal:led,key` 合格，`rtos移植` 不合格）
- 提交前自查：零编译告警、`--print-memory-usage` 无意外增长、cppcheck（CI 接入后强制）
- `build/` 产物当前被跟踪进仓库（见 9. 已知问题），提交时避免混入无关构建产物 diff

## 8. 问题定位指南

### 8.1 排查总纲（按顺序问）

1. **供电**：电机电源电压/纹波（TB6612 VM 独立供电？共地？）
2. **时钟**：HSE 是否起振（PLLRDY）？SystemCoreClock 与实际一致？
3. **引脚复用**：对照《需求分析》2.1.2 映射表查冲突
4. **中断优先级**：ISR 里调了 FromISR API 但 NVIC 数值 < 2？-> FreeRTOS assert / 死机
5. **看门狗**：当前未启用 IWDG（待办），死机先查死循环而非复位

### 8.2 常见症状速查

| 症状 | 高概率原因 | 验证手段 |
| ---- | ---------- | -------- |
| 上电即 HardFault | 向量表/时钟/启动文件问题；链接脚本不匹配 | GDB `bt` + fault_handlers 打印的 PC/LR |
| 开中断后偶发 HardFault | ISR 优先级违反 FreeRTOS 约定；栈溢出 | 检查 NVIC 分组与数值；栈水位 |
| I2C 无 ACK | 总线卡死（从机拉死 SDA） | bsp_i2c 自带总线恢复序列（含 SCL 钳位检测），看错误码；逻辑分析仪抓波形 |
| OLED / MPU6050 同时失效 | I2C1 总线级故障（互斥锁泄漏？） | 复现路径 + 检查所有 I2C 事务是否走锁 |
| 任务不运行 | 优先级配错 / 栈溢出 / 创建失败返回值未查 | GDB 看 `pxReadyTasksLists`；查 `xTaskCreate` 返回值 |
| 逻辑对了但控制发散 | PID 符号方向 / 电机左右接反 / 角度轴向不对 | 架空车轮，开环小占空比逐环验证 |
| printf 无输出 | **当前已知**：nosys 下无 `_write` 重定向 | 见 9. 待办；暂用 GDB / ITM |

### 8.3 HardFault 分析流程（实操）

```
1. 调试器连接，让程序死在 bkpt
2. 读 fault_handlers 打印（或 GDB 手动）：
   - PC（出错指令）、LR（返回地址，定位调用者）
   - CFSR：IBUSERR/PRECISERR/IMPRECISERR/UNDEFINSTR/INVSTATE...
   - 栈帧中的 R0-R3 常是坏指针来源
3. addr2line 定位源码行：
   arm-none-eabi-addr2line -e build/app/stm32f103_test.elf -f -C 0x<PC>
4. INVSTATE 高发于：函数指针未初始化（跳到 data 区）、
   Thumb 位丢失（函数地址 |1 缺失）-- 查回调/ops 表填充时机
```

### 8.4 逻辑分析仪测量点位

- 控制任务入口翻转 GPIO -> 测周期/抖动（SRS FR-CTRL-001 验证方法）
- I2C SCL/SDA + UART 波形 -> 核对 400kHz / 115200-8N1
- PWM 输出 PA8/PA9 -> 核对 20kHz 与占空比线性度
- EXTI 按键波形 -> 验证 20ms 消抖
